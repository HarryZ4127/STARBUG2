Starbug ISA Trade Study

How much each proposed ISA change buys on 16 kernels: the team's 10 Embench DSP kernels plus integer DSP, ML and control code. Every number comes from MPACT instruction traces replayed through a timing model checked against the RTL.

What the numbers say

  1. A second memory path is the only change that moves the needle, and only if the two accesses don't collide. Over today's Starbug (geomean, all 16 kernels): a load-only second path gives +29%, a second full load/store path +37%, when every paired access lands in a different bank. With plain two-bank word interleaving and the data where the linker put it, the same paths give +14% and +21%. Bank conflicts take about half the gain.
  2. 8-wide is not worth it with one or two memory ports. 8-wide with one memory op per bundle: +0%. 8-wide with two load/store paths: +22%, about the same as 4-wide with two paths (+21%). Width only starts to matter at four memory ops per bundle (1.54× at 4-wide vs 1.62× at 8-wide).
  3. Branch features are small once the compiler unrolls. gshare predictor +7%, static backward-taken prediction +5%, zero-overhead loops +7%. Without unrolling they are worth up to 1.7× on tight loops, which is where the earlier "up to 4×" estimate comes from.
  4. The compiler is the largest lever. Unrolling plus splitting reductions over several accumulators makes the same Starbug run 1.7–2.6× faster on FIR, LMS, EDN, matrix multiply and Q15 FIR. That is more than any hardware change above.
  5. The 32-bit header costs no cycles; predication buys almost none. The header grows the hot code by 14%. About 9% of bundles would straddle a 64-byte I-cache line, which today's fetch logic can't issue as a bundle. creg/z predication has something to remove only in the Q15 FIR's saturation (2.9% of cycles); GCC has already made every other kernel branch-free.
  6. Today's baseline comparison is unequal. The starbug config runs without the branch predictor the rv32gc baseline has (BPRED_SUPPORTED = 0 vs gshare), so the 1.40× in the weekly report understates the VLIW part.

Answers to the open questions in the 10.09 report

One load/store path plus one load-only path, instead of two full paths?

Yes. It captures 76% of the two-full-path gain (+29% vs +37%). The gap is in kernels that store inside the loop: LMS (1.50× vs 1.72×) and the in-place DCT/FFT butterflies. It also avoids two stores in one cycle, which removes the store–store and load–store hazards between the paths.

Should the compiler place data in the interleaved region, or should hardware handle bank conflicts?

Hardware conflict stalls alone keep roughly half the benefit (+14% instead of +29% for the load-only path). The other half needs placement: put the two streams a kernel reads together (samples and coefficients, input and weights) in opposite banks, or give each its own memory region, as DSPs with separate X/Y memories do. Plan for both: stall on a conflict so the hardware is correct, and have the compiler or linker separate the hot arrays.

Is the marginal target of ≥1.2× over current Starbug the right level?

It is reachable but not automatic. Load-only path with naive interleaving: 1.14×, a miss. Same with gshare and zero-overhead loops: 1.27×. Load-only path with conflict-free placement: 1.29×. The ideal target should name the data-placement work, because that decides which side of 1.2× the design lands on.

P-bit chaining or a second header word for 8-wide?

On this suite it doesn't matter for size: 8-wide bundles average under four ops, so both encodings produce the same bytes. Given that 8-wide gains about 1% here, the 8-wide encoding can stay unresolved while the second memory path goes first.

Hot code is every basic block the benchmarks execute in their timed region, laid out contiguously. A straddling bundle is one whose bytes cross a 64-byte I-cache line. Today's RTL refuses to issue those as bundles and runs them as scalar code. With the 32-bit header there is no scalar fallback, so the assembler has to align them or the fetch logic has to read across lines; the "continuous fetching" item on the goal list covers this. If each straddle cost one cycle, that would be 7.3% of 4-wide cycles.

How the model was built and checked

  • Traces. MPACT rv32g_sim, patched to log every retired PC and data address and to stub the 16550 UART, so the cvw bare-metal ELFs run unchanged. All 42 runs pass their own self-checks (SNR or verify).
  • Code. The team's 10 Embench DSP kernels (cvw lm/fp examples/C/embench_starbug), Embench-IoT crc32, nettle-sha256, matmult-int and edn, plus an int8 depthwise conv and a Q15 FIR written for this study. All are built with GCC 10.2, -O3, rv32imafc. The unrolled build adds Leo's VLIW-seed flags and -fvariable-expansion-in-unroller.
  • Timing. In-order, lock-step bundles. Load, multiply and FP results are ready after 2 cycles, ALU results after 1 (Wally's LoadStallD, MDUStallD, FPUStallD). A taken branch or misprediction costs 2 cycles. 16 KB 4-way I and D caches, 18-cycle line fill. Lanes follow the RTL: memory, branches and CSRs in lane 0 only.
  • Scheduling. A list scheduler packs each basic block into bundles for the configuration under test. Within a block, memory ops are treated as independent when their traced addresses never overlap. No software pipelining across iterations: unrolling stands in for it.
Against Leo's Questa runs, the model's median error is 4.4% for hand-written VLIW code on Starbug and 3.9% on RV32GC (8 and 10 of 10 kernels within 10%). The model puts Starbug at 1.49× over scalar where the RTL measured 1.40×.

Limits

  • The scheduler stands in for a compiler that doesn't exist yet. Hand scheduling or modulo scheduling could find more parallelism; the ceiling row (1.86×) shows how much this code holds when resources stop binding.
  • Cycle counts only. Area and clock are not modelled: a second memory path or 8 lanes may cost frequency that the 50 MHz target has to absorb.
  • Bank conflicts use word interleaving and the addresses the linker produced. A layout tuned per kernel would land between the "2 banks" and "no conflicts" rows.
  • The earlier estimates in the weekly report (2.7–3.1× for a second load path, up to 4× for low-overhead branches) are not reproduced here. They were measured against different baselines; numbers from the two studies shouldn't be mixed in the DFD.
